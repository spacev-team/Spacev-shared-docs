# 한 치의 망설임도 없이, 존댓말로, 진지하게
왜 생기는가

AI는 "다음에 올 말"을 확률로 예측하는 기계다. 사실을 알고 답하는 게 아니라 가장 자연스러운 문장을 만든다.

그럴듯할수록 위험

판례 번호·논문 제목·수치처럼 형식이 완벽한 것부터 의심한다.

그래서 답은

환각은 버그가 아니라 작동 원리 — 없앨 수 없다. "더 좋은 AI 고르기"가 아니라 사람이 검증하는 절차가 답이다.

요즘 모델은 이 질문엔 안 속는다. 대신 티가 안 나는 지점에서 틀린다.

Part 2 · 연동 규정

Google Sheets 연동 — 공용 서비스 계정 사용

1

서비스 계정 키 받기

사내 담당자에게 공용 서비스 계정의 JSON 키를 받아, Claude Code 작업 폴더 최상단에 둔다. 이 파일이 비밀번호 역할을 한다.

2

계정 이메일 확인

google-automation@spacev-ai-tf.iam.gserviceaccount.com

3

시트에 초대

작업할 시트의 "공유"에 이 이메일을 추가한다. 권한은 편집자, 읽기만이면 뷰어. 알림 보내기는 해제.

계정을 직접 만들지 않는다 — 공용 서비스 계정 하나로 접근을 관리한다.

원칙 3

승인된 것만 연결

출처가 불분명한 MCP 서버·플러그인은 설치하지 않는다. 정책의 "출처 불분명 서비스 금지"가 그대로 적용된다.

원칙 1

최소 권한으로 연결

읽기만 필요하면 읽기 권한만 연결한다. Drive·Slack·GitHub 전체 접근 권한을 습관적으로 주지 않는다.

MCP는 AI에게 실행 능력을 주는 일이다. 편리해지는 만큼 Part 2 정책이 그대로 적용된다.

# 계획만 먼저 요청
7월 1:1 문의 목록으로 답변 초안을 만들 거야.
아직 아무것도 실행하지 말고,
작업 계획만 단계별로 보여줘

# AI 응답
계획: ① 목록 확인 → ② 개인정보 마스킹
     ③ 유형별 분류 → ④ 모범답안 조회
     ⑤ 초안 작성 → 시트 저장
이대로 진행할까요? ← 여기서 사람이 검토
순서가 말이 되는가

내가 손으로 한다면 이 순서가 맞는지 본다.

위험한 단계가 있는가

파일 삭제·덮어쓰기·외부 전송·대량 발송이 계획에 있으면, 그 단계 앞에 "멈추고 확인받아"를 추가한다.

빠진 것은 없는가

원하는 산출물(초안? 시트? 분류표?)이 계획의 끝에 있는지 본다.

계획 검토 30초가 실행 후 수습 30분을 아낀다.

# 계획 승인 + 정지 조건
좋아, 계획 승인. 단, 각 단계가 끝나면
결과를 보여주고 멈춘 뒤 내 확인을 받고 진행해

# 1단계 결과
✔ 유형 분류 완료 — 환불 12건 · 예약변경 8건
  확인 후 2단계로 진행할까요?

환불 12건 중 2건은 위약금 문의인데? 다시 분류해
← 3단계가 아니라 1단계에서 잡음
오류는 증폭된다

1단계 분류가 틀리면 초안 25건이 전부 틀린다. 단계마다 확인하면 오류가 작을 때 잡힌다.

승인 모드가 자동 체크포인트

파일 수정·명령 실행 전에 AI가 먼저 물어본다.

어디에 둘까

결과물이 다음 단계의 재료가 되는 지점마다 체크포인트를 둔다.

중간에 멈추는 것은 느린 것이 아니다 — 틀린 채로 끝까지 가는 것이 느린 것이다.
