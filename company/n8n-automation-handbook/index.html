이 문서를 읽기 전에

이 핸드북은 개발을 해본 적 없는 마케터·기획자·운영 담당자를 1순위 독자로 가정했습니다. "API", "트리거", "워크플로우" 같은 단어가 처음 나올 때마다 뜻을 먼저 풀어서 설명하니, 익숙한 분은 용어 설명을 건너뛰고 단계만 따라가셔도 됩니다.

무엇을 만들게 되나요?

끝까지 따라 하면 코드를 한 줄도 쓰지 않고, 평소 말하듯 한 문장(자연어)으로 아래 두 가지 자동화를 직접 만들어 회사 서버에서 돌아가게 할 수 있습니다.

받은 메일 AI 요약·분류

새 메일을 AI가 요약하고 중요도를 판단해, 중요한 것만 구글 챗으로 알립니다.

경쟁사 소식 모니터링

경쟁사 소식(RSS)을 AI가 요약해 스프레드시트에 자동으로 누적합니다.

두 가지를 만들고 나면, 같은 방식으로 "내 업무"에 맞는 자동화를 스스로 설계할 수 있게 됩니다. 그게 이 문서의 진짜 목표입니다.

이 작업의 본질은 "프로그램을 짜는 것"이 아니라 "하고 싶은 일을 말로 정확히 설명하는 것"입니다. 어려운 건 도구(Claude)가 하고, 우리는 "무엇을, 언제, 어디로"만 분명히 정해 주면 됩니다.

1 · 개념

먼저 알아야 할 개념

실습 전에 "지금 우리가 뭘 하려는 건지"를 그림으로 잡고 갑니다. 이 장만 이해해도 절반은 끝납니다.

'업무 자동화'가 뭔가요?

사람이 매번 손으로 하던 반복 작업을, 정해진 규칙에 따라 컴퓨터가 알아서 처리하게 만드는 것입니다. 예를 들어 "메일이 오면 → 내용을 요약해서 → 팀 채팅방에 올린다"를 매번 직접 하는 대신, 한 번 만들어 두면 컴퓨터가 24시간 알아서 반복합니다.

자동화는 거의 항상 세 토막으로 이루어집니다. 이 셋만 기억하면 됩니다.

트리거 언제 자동화를 시작시키는 신호
가공 무엇을 AI가 요약 · 분류 · 정리
액션 어디로 채팅 · 시트 등에 결과 전달
용어 풀이
  • 트리거(Trigger) — 자동화의 시작 버튼. "새 메일이 도착하면", "매일 아침 9시가 되면"처럼 시작 조건을 말합니다.
  • 노드(Node) — '메일 읽기', 'AI로 요약하기'처럼 하나하나의 작업 블록. 레고 블록이라고 생각하세요.
  • 워크플로우(Workflow) — 노드(블록)를 순서대로 연결한 자동화 한 세트. 우리가 만들 결과물이 바로 이것입니다.

두뇌 · 목 · 몸 — 세 도구의 역할

우리는 세 가지 도구를 씁니다. 사람 몸에 비유하면 이해가 쉽습니다.

두뇌

Claude Code

말로 한 요청을 이해하고, 어떤 블록을 어떤 순서로 연결할지 설계합니다. 단, 두뇌 혼자서는 실제 실행을 못 합니다.

목

n8n-MCP

두뇌의 설계를 n8n이 알아듣는 언어로 번역·검증해 전달하는 중간 다리입니다. 이게 없으면 두뇌가 블록 이름을 '추측'해서 오류가 잦습니다.

몸

n8n

실제로 워크플로우를 실행하는 자동화 엔진. 회사 서버에서 24시간 돌아갑니다.

한 문장 요약

자연어 요청 → 설계(두뇌) → 번역·배포(목) → 24시간 실행(몸). 이 흐름이 이 문서 전체를 관통합니다.

왜 하필 n8n인가요?

자동화 도구는 Zapier, Make 등 여러 가지가 있습니다. 그중 회사가 n8n을 쓰는 이유는 세 가지입니다.

이유 설명
유연성 · 확장성 오픈소스라 특정 회사에 종속되지 않고, 필요하면 맞춤 기능까지 만들 수 있습니다.
강력한 데이터 처리 여러 건을 한 번에 처리하고, 복잡한 분기·병합도 자유롭습니다.
비용 · 데이터 주권 회사 서버에 직접 설치(셀프호스팅)해 무료로 쓰고, 민감 데이터를 외부로 보내지 않습니다.

삼삼엠투는 이미 자체 서버에서 n8n을 운영하고 있어, 우리는 그 위에 워크플로우만 얹으면 됩니다.

2 · 준비 ①

Claude Code 설치

'두뇌'를 내 컴퓨터에 설치하는 단계입니다. 화면을 따라 그대로 누르면 됩니다.

Claude Code가 뭔가요?

Anthropic이 만든 AI 도구입니다. 채팅처럼 말로 요청하면, 파일을 만들고 고치고 다른 프로그램과 연결하는 일까지 대신 해 줍니다. 우리는 이걸 '두뇌'로 사용합니다.

✓ 미리 받아두세요

설치 파일은 용량이 있어 다운로드에 시간이 걸릴 수 있습니다. 본 실습 전에 미리 받아두면 "로그인 후 실행"부터 바로 시작할 수 있습니다.

1단계 · 데스크탑 버전 내려받기

  1. 공식 사이트 접속 — 브라우저에서 https://claude.com/ko/download 로 접속합니다.
  2. 내 운영체제용 설치 파일 다운로드 — Windows면 Windows용(.exe), Mac이면 Mac용 데스크탑 앱을 받습니다.
  3. 설치 실행 — 받은 파일을 더블클릭하고 안내(다음 → 다음)에 따라 설치를 끝냅니다.
  4. 로그인 준비 — 설치가 끝나면 Claude 계정으로 로그인할 준비를 합니다.

2단계 · 실행하고 Claude Code 열기

  1. 설치한 데스크탑 앱 실행 — 바탕화면 또는 시작메뉴(Mac은 런치패드)에서 앱을 엽니다.
  2. 계정으로 로그인 — Claude 계정으로 로그인합니다. 회사에서 안내한 계정이 있으면 그것을 사용하세요.
  3. Claude Code 화면으로 진입 — 앱 안에서 코드(Code) 화면으로 들어가면, 폴더를 고르고 아래 입력창에 말로 요청하는 화면이 보입니다.

체크포인트 — 여기까지 됐나요?

다음 세 가지가 모두 '예'면 두뇌 준비 완료입니다.

데스크탑 앱이 오류 없이 열렸다.
내 계정으로 로그인된 상태다.
명령(요청)을 입력할 수 있는 화면이 보인다.
! 안 될 때

설치 중 막히면 혼자 오래 붙잡지 말고 담당자(또는 사내 자동화 채널)에 화면을 캡처해 문의하세요. 설치는 한 번만 넘기면 이후 실습은 매끄럽게 진행됩니다.

3 · 준비 ②

n8n · n8n-MCP 연결

'몸(n8n)'에 접속하고, '목(n8n-MCP)'을 붙여 두뇌가 회사 서버에 직접 워크플로우를 만들 수 있게 합니다.

3-1 · n8n 접속과 화면 둘러보기

먼저 회사 자체 서버의 n8n에 접속합니다.

항목 값
서버 주소 https://n8n-internal.33m2.co.kr
계정(ID) 담당자가 안내 (예: 실습용 계정)
비밀번호 담당자가 현장/별도 안내
화면에서 보게 될 3가지 개념

트리거(시작 신호), 노드(작업 블록), 워크플로우(블록을 연결한 자동화 한 세트). 1장에서 설명한 그 개념이 실제 화면에 그대로 나타납니다.

3-2 · n8n-MCP 설치 (두뇌에 '목' 붙이기)

n8n-MCP가 왜 필요한가요?

두뇌(Claude)가 n8n의 블록 이름·설정을 '추측'하면 오류가 잦습니다. n8n-MCP는 정확한 블록 정보를 두뇌에게 알려주고, 만든 워크플로우를 검증해 안전하게 배포하도록 돕는 다리입니다.

방법 1 (추천 · 가장 쉬움) — 깃허브 링크를 주고 부탁하기

Claude Code 입력창에 아래처럼 링크와 함께 부탁하면, Claude가 알아서 설치·설정합니다.

https://github.com/czlonkowski/n8n-mcp 이 MCP 서버를 설치해줘

Claude가 문서를 읽고 설정을 구성·등록합니다. 설치 후 Claude Code를 한 번 재시작하고, 도구가 인식되는지만 확인하면 됩니다.

방법 2 (수동) — 설정을 직접 붙여넣기

직접 설정하려면 아래 기본 구성을 설정 파일에 넣습니다.

// 기본 구성 (문서·검증 도구만 사용)
{
  "mcpServers": {
    "n8n-mcp": {
      "command": "npx",
      "args": ["n8n-mcp"],
      "env": { "MCP_MODE": "stdio", "LOG_LEVEL": "error" }
    }
  }
}

3-3 · 회사 n8n 서버와 연결 (워크플로우 자동 배포)

여기까지 하면 두뇌가 회사 서버에 직접 워크플로우를 만들고 배포할 수 있습니다.

// 풀 구성 (생성·실행·배포까지 가능) — 회사 n8n 서버 연결
"env": {
  "MCP_MODE": "stdio",
  "LOG_LEVEL": "error",
  "N8N_API_URL": "https://n8n-internal.33m2.co.kr/api/v1",
  "N8N_API_KEY": "<발급받은 키를 여기에 — 개인별로 입력>"
}
! API Key 다루는 법 (중요)

API Key는 비밀번호와 같습니다. 이 문서에는 실제 키를 적지 않습니다. 각자 n8n에서 발급해 본인 설정에만 넣고, 실습이 끝나면 n8n Settings에서 삭제(재발급)하세요. 키가 만료되면 새로 발급한 뒤 같은 자리에 교체하면 됩니다.

연결 순서는 다음과 같습니다.

  1. n8n 로그인 — 위 서버 주소로 접속해 로그인합니다.
  2. API Key 발급 — n8n 화면에서 Settings → n8n API → Create API Key로 키를 발급합니다.
  3. 풀(full) 구성에 입력 — 발급한 키와 API 주소를 위 설정에 붙여넣습니다.
  4. 연결 확인 — Claude Code를 재시작한 뒤 n8n 도구가 인식되는지 확인합니다.

3-4 · 안전 수칙

수칙 이유
운영 워크플로우 직접 편집 금지 실제로 돌고 있는 자동화를 AI로 바로 고치면 사고로 이어질 수 있습니다.
복사본·테스트 환경에서 먼저 검증 사본을 만들어 충분히 확인한 뒤 운영에 반영합니다.
배포 전 검증(validate) 변경 사항을 배포 전에 반드시 점검합니다.
백업·버전 관리 중요한 워크플로우는 '내보내기'로 백업해 둡니다.
운영(라이브) API 과호출 금지 워크플로우가 실제 서비스 API를 짧은 주기로 대량 호출하면 라이브 장애를 일으킬 수 있습니다.
! 실제 사고 사례 — 방 검색 API 대량 호출

한 워크플로우가 사내 방 검색 API(/v1/rooms, /v1/rooms/count)를 약 3분간 동일 요청으로 500건 이상 호출해, 라이브 API 오류로 일부 사용자의 방 검색·지도 화면이 일시적으로 동작하지 않은 일이 있었습니다.

예방하려면

  • 운영 API를 호출하는 워크플로우는 호출 주기와 건수를 반드시 제한합니다.
  • 같은 요청을 무한 반복(루프)하지 않도록 종료 조건·페이지네이션을 확인합니다.
  • 테스트는 소량(1~2건)으로, 분 단위 등 짧은 주기 트리거는 특히 주의합니다.
  • 내 워크플로우가 어떤 API를 얼마나 자주 호출하는지 항상 인지합니다.
4 · 실습 1

받은 메일 AI 요약·분류

새 메일이 오면 AI가 요약하고 중요도를 판단해, 중요한 것만 구글 챗으로 알리는 자동화를 만듭니다.

무엇을 만드나 (완성 그림)

트리거 · Gmail 언제 새 메일 수신을 감지
AI 가공 · Gemini 무엇을 3줄 요약 + 중요도(상·중·하)
액션 · 구글 챗 어디로 중요도 '상'만 알림

준비물

  • Gmail 계정 — n8n에 연결할 권한
  • AI(예: Gemini) API 키 — 요약을 맡길 AI
  • 구글 챗 스페이스와 Webhook 주소 — 알림을 받을 곳
Webhook이 뭔가요?

"여기로 메시지를 보내면 이 채팅방에 표시된다"는 전용 주소입니다. 구글 챗 스페이스 설정에서 만들 수 있고, 이 주소로 자동화가 알림을 보냅니다.

STEP 1 · Claude Code에 이렇게 요청하세요

내 Gmail에 새 메일이 오면 본문을 3줄로 요약하고 중요도를
상·중·하로 분류해줘. 중요도가 '상'인 메일만 제목·요약·발신자를
구글 챗 스페이스로 보내줘.
✓ 좋은 요청을 쓰는 공식

트리거(언제) + 가공 규칙(무엇을 어떻게) + 조건(어떤 경우만) + 도착지(어디로)를 구체적으로 적으면, 결과가 훨씬 정확해집니다.

STEP 2 · Claude가 설계·검증하는 과정

요청을 보내면 Claude가 n8n-MCP로 필요한 블록을 찾아 연결하고 오류를 점검합니다. 실제 실습에서는 다음 5개 노드로 구성되었습니다.

Gmail 트리거→ Gemini 요약·분류→ 응답 파싱→ 중요도 '상' 필터→ Google Chat

Claude가 "이렇게 구성했습니다"라고 보여주면, 내용을 확인하고 진행을 승인하세요. (참고: 요약은 Gemini를 HTTP 요청으로 호출했고, 알림은 기존 구글 챗 Webhook을 재활용했습니다.)

STEP 3 · 배포 & 계정 연결

Claude가 회사 n8n 서버에 워크플로우를 만들어 배포합니다(워크플로우 ID가 자동 생성됨). 그다음 계정 연결은 본인이 직접 합니다.

  • n8n 화면에서 Gmail 로그인(자격 증명) 연결
  • AI(Gemini) API 키 입력
  • 구글 챗 Webhook 주소 입력

STEP 4 · 실행하고 STEP 5 · 확인

  1. 워크플로우 활성화(Active) — Active로 켜면 트리거가 메일을 감시하기 시작합니다.
  2. 테스트 — 나에게 테스트 메일을 보내거나, 상단의 Execute workflow로 한 번 직접 실행합니다.
  3. 결과 확인 — 필터를 통과한 '상' 중요도 메일이 제목·요약·발신자와 함께 구글 챗에 도착하면 성공입니다.

5 · 실습 2

경쟁사 블로그·SNS 모니터링

정해진 주기로 경쟁사 소식(RSS)을 확인해, AI가 요약하고 스프레드시트에 자동으로 쌓는 자동화를 만듭니다.

RSS가 뭔가요?

블로그·뉴스 사이트가 "새 글이 올라왔다"를 기계가 읽기 쉬운 형태로 제공하는 구독 주소입니다. 이 주소를 주기적으로 확인하면 새 글을 자동으로 감지할 수 있습니다.

무엇을 만드나 (완성 그림)

트리거 · RSS 1시간마다 새 글 발행 확인
AI 가공 · Gemini 무엇을 HTML 제거 후 3줄 요약
액션 · 스프레드시트 어디로 행으로 누적 기록

준비물

  • 모니터링할 RSS 주소 (실습 예: news.airbnb.com/ko/feed)
  • AI(Gemini) API 키
  • 구글 스프레드시트 — 서비스 계정에 '편집자' 권한 필요 (아래 막힘 사례 참고)

STEP 1 · Claude Code에 이렇게 요청하세요

에어비앤비 뉴스 RSS(news.airbnb.com/ko/feed)를 1시간마다
확인해서 새 글을 3줄로 요약하고, 날짜·제목·요약·링크를 구글
스프레드시트 '에어비앤비 최신 뉴스 백업'에 한 행씩 추가해줘.
✓ 팁

확인 주기(예: 1시간), 요약 형식(예: 3줄), 저장할 항목(날짜·제목·요약·링크)을 분명히 적으면 원하는 결과가 바로 나옵니다.

STEP 2 · Claude가 설계·검증하는 과정

실제 실습에서는 다음과 같은 노드 구성으로 만들어졌습니다.

스케줄(1시간)→ RSS 읽기→ 내용 정제→ Gemini 요약→ 요약 추출→ Google Sheets 기록

STEP 3 · 배포 & 계정 연결

회사 n8n에 배포된 뒤, 구글 시트에 접근할 수 있도록 서비스 계정 자격 증명을 n8n에 연결합니다.

! 주기 설정 주의

RSS 같은 외부 사이트나 사내 API를 너무 짧은 주기(예: 1분마다)로 부르면 상대 서버에 부담을 주거나 차단될 수 있습니다. 보통 30분~1시간 이상으로 넉넉히 잡고, 사내 운영 API라면 더 보수적으로 설정하세요.

STEP 4 · 실행하고 STEP 5 · 확인

  1. 워크플로우 활성화(Active) — Active로 켜면 설정한 주기(1시간)마다 자동 실행됩니다.
  2. 테스트 — 기다리지 말고 상단 Execute workflow로 즉시 한 번 실행해 봅니다.
  3. 결과 확인 — '에어비앤비 최신 뉴스 백업' 시트에 날짜·제목·요약·링크 새 행이 쌓이면 성공입니다.

꼭 지킬 안전 수칙 (다시 강조)

  • 배포 전 검증, 배포 후 백업. 중요한 워크플로우는 내보내기로 보관합니다.

  • 민감 데이터는 외부로 보내지 않기. 회사 서버(n8n) 안에서 처리합니다.
  • 운영(라이브) API를 과도하게 호출하지 않기. 짧은 주기·대량 반복 호출은 실제 서비스 장애로 이어질 수 있으니, 주기·건수를 제한하고 테스트는 소량으로 합니다. (실제 사고 사례: 3장 참고)

자주 묻는 질문(FAQ)

Q. 코딩을 전혀 몰라도 되나요?

네. 말(자연어)로 요청하면 Claude가 대신 만듭니다. 우리가 할 일은 "무엇을·언제·어디로"를 분명히 정하는 것뿐입니다.

Q. 잘못 만들면 회사 시스템이 망가지나요?

운영 중인 워크플로우를 직접 수정하지 않고, 새로 만든 것을 테스트로 먼저 확인하면 안전합니다. 안전 수칙(6장)을 지키세요.

Q. AI 요약 결과가 이상해요.

요청에 요약 형식(예: 3줄), 기준(예: 중요도 상·중·하)을 더 구체적으로 적어 다시 요청하세요. 프롬프트가 구체적일수록 결과가 좋아집니다.

Q. '자격 증명 오류'가 나요.

계정 연결(Gmail 로그인, AI 키, 구글 챗/시트 권한)이 빠졌을 가능성이 큽니다. 각 노드의 자격 증명이 연결됐는지 확인하세요. 시트는 '서비스 계정을 편집자로 공유'했는지 꼭 확인합니다.

Q. 자동화가 안 돌아가요.

① 워크플로우가 Active(활성화) 상태인지, ② 트리거 조건이 맞는지, ③ 자격 증명이 연결됐는지 순서대로 점검하세요.

Q. 자동화가 회사 서비스에 부담을 줄 수도 있나요?

네. 워크플로우가 운영 중인 API를 짧은 주기로 대량 호출하면 실제 라이브 장애를 일으킬 수 있습니다(3장 사고 사례 참고). 호출 주기를 넉넉히 잡고, 같은 요청을 반복하지 않도록 종료 조건을 확인하며, 테스트는 소량으로 하세요.

Q. API Key가 만료됐어요.

n8n Settings에서 새로 발급한 뒤, 설정의 같은 자리(N8N_API_KEY)에 교체해 넣으면 됩니다.
