0.이 문서를 읽기 전에

이 핸드북은 "크롤링? 코딩? 나랑은 먼 얘기"라고 생각하는 분을 위해 만들었습니다.

누구를 위한 문서인가요?

개발을 해본 적 없는 마케터·기획자·운영 담당자를 1순위 독자로 가정했습니다. 그래서 "크롤링", "API", "셀렉터" 같은 단어가 처음 나올 때마다 뜻을 먼저 풀어서 설명합니다. 이미 익숙한 분은 용어 설명을 건너뛰고 단계만 따라가셔도 됩니다.

무엇을 만들게 되나요?

이 문서를 끝까지 따라 하면, 코드를 한 줄도 쓰지 않고 자연어(평소 말하듯 한 문장)로 아래 네 가지 자동 수집을 직접 만들 수 있습니다.

실습 ①·②
경쟁사 숙소 개수 · 앱 버전을 매일 자동 수집 → 구글 시트에 기록
실습 ③·④
마라톤 대회 신청 정보(로그인 X) · AirDNA 방 개수(로그인 O)를 수집 → 시트·챗 알림

네 가지를 만들고 나면, 같은 방식으로 "내 업무"에 맞는 수집을 스스로 설계할 수 있게 됩니다. 그게 이 문서의 진짜 목표입니다.

미리 준비하면 좋은 것

  • 인터넷이 되는 Windows 또는 Mac 노트북
  • 회사 Google 계정 (구글 시트·구글 챗 사용)
  • 수집하고 싶은 웹사이트 주소 1~2개 (실습은 예시로 진행)
  • 약 두 시간의 집중 가능한 시간
✓핵심 마인드셋
이 작업의 본질은 "프로그램을 짜는 것"이 아니라 "모으고 싶은 데이터를 말로 정확히 설명하는 것"입니다. 어려운 건 도구(Claude)가 하고, 우리는 "어디서 · 무엇을 · 어디에 쌓을지"만 분명히 정해 주면 됩니다.

1.먼저 알아야 할 개념

실습 전에 "지금 우리가 뭘 하려는 건지"를 그림으로 잡고 갑니다. 이 장만 이해해도 절반은 끝납니다.

'크롤링'이 뭔가요?

사람이 브라우저로 웹사이트를 열어 눈으로 확인하던 것을, 코드가 대신 자동으로 열어서 원하는 데이터를 읽어오는 것입니다. 예를 들어 "경쟁사 사이트에 접속 → 숙소 개수 숫자를 확인 → 시트에 적는다"를 매번 직접 하는 대신, 한 번 만들어 두면 컴퓨터가 반복합니다.

크롤링은 거의 항상 세 토막으로 이루어집니다. 이 셋만 기억하면 됩니다.

i용어풀이

크롤링(Crawling) — 웹페이지를 자동으로 열어 데이터를 긁어오는 것. 스크래핑(Scraping)과 거의 같은 뜻으로 씁니다.

API — 사이트가 데이터를 프로그램용으로 깔끔하게 내려주는 '공식 창구'. 있으면 크롤링보다 쉽고 안정적입니다.

셀렉터(Selector) — 페이지 안에서 "이 위치의 이 값" 하고 콕 집어 가리키는 주소. 어려워 보이지만 Claude가 알아서 찾습니다.

API가 있으면 API, 없으면 크롤링

데이터를 얻는 방법은 두 가지입니다. 공식 API가 있으면 API를 먼저 쓰고(빠르고 안정적), 없거나 로그인·화면 조작이 필요하면 크롤링을 씁니다. 실습 ①은 API 방식, ②~④는 브라우저를 직접 여는 크롤링 방식에 가깝습니다.

!크롤링 전에 반드시 확인하세요
  • 공개된 데이터만 대상으로 합니다(로그인 뒤 개인정보·유료 데이터 무단 수집 금지).
  • 사이트 이용약관과 robots.txt를 존중합니다.
  • 과도한 요청 금지 — 짧은 주기로 대량 호출하면 상대 서버에 부담을 주고 차단될 수 있습니다.

두뇌·손가락 — 두 도구의 역할

우리는 두 가지 도구를 씁니다. 사람에 비유하면 이해가 쉽습니다.

두뇌 — Claude Code

우리가 말로 한 요청을 이해하고, 어떤 페이지에서 무엇을 어떻게 읽을지 코드로 설계·작성합니다. 단, 두뇌 혼자서는 실제로 브라우저를 못 엽니다.

손가락 — Playwright

두뇌가 만든 코드를 받아 진짜 브라우저를 실행해서 페이지를 열고, 클릭하고, 로그인하고, 데이터를 읽습니다. 사람이 마우스로 하던 걸 대신하는 손가락입니다.

iPlaywright란?
Microsoft가 만든 브라우저 자동화 도구입니다. 화면 없는 단순 요청과 달리 진짜 크롬을 띄워 자바스크립트로 그려지는 페이지, 로그인이 필요한 페이지까지 사람처럼 읽을 수 있습니다. 그래서 "손가락"으로 씁니다.
✓한 문장 요약
자연어 요청 → 설계·코드(두뇌 Claude) → 브라우저 실행·데이터 읽기(손가락 Playwright) → 구글 시트 기록·챗 알림. 이 흐름이 이 문서 전체를 관통합니다.

2.준비 ① Claude Code 설치

'두뇌'를 내 컴퓨터에 설치하는 단계입니다. 화면을 따라 그대로 누르면 됩니다.
iClaude Code가 뭔가요?
Anthropic이 만든 AI 도구입니다. 채팅처럼 말로 요청하면, 파일을 만들고 고치고 다른 프로그램과 연결하는 일까지 대신 해 줍니다. 우리는 이걸 '두뇌'로 사용합니다.

1단계 · 데스크탑 버전 내려받기

1
공식 사이트 접속브라우저에서 https://claude.com/download 로 접속합니다.
2
내 운영체제용 설치 파일 다운로드Windows면 Windows용, Mac이면 Mac용 데스크탑 앱을 받습니다.
3
설치 실행받은 파일을 더블클릭하고 안내(다음 → 다음)에 따라 설치를 끝냅니다.
✓미리 받아두세요
설치 파일은 용량이 있어 다운로드에 시간이 걸릴 수 있습니다. 실습 전에 미리 받아두면 "로그인 후 실행"부터 바로 시작할 수 있습니다.

2단계 · 실행하고 Claude Code 열기

1
설치한 데스크탑 앱 실행바탕화면 또는 시작메뉴(Mac은 런치패드)에서 앱을 엽니다.
2
계정으로 로그인Claude 계정으로 로그인합니다. 회사에서 안내한 계정이 있으면 그것을 사용하세요.
3
Code 화면으로 진입앱 안에서 Code(코드) 화면으로 들어가면, 작업 폴더를 고르고 요청을 입력하는 화면이 보입니다.

체크포인트 — 여기까지 됐나요?

다음 세 가지가 모두 '예'면 두뇌 준비 완료입니다.

  • 데스크탑 앱이 오류 없이 열렸다
  • 내 계정으로 로그인된 상태다
  • 요청(명령)을 입력할 수 있는 화면이 보인다
!안 될 때
설치 중 막히면 혼자 오래 붙잡지 말고 담당자(또는 사내 자동화 채널)에 화면을 캡처해 문의하세요. 설치는 한 번만 넘기면 이후 실습은 매끄럽게 진행됩니다.

3.준비 ② 작업환경 연결

수집한 데이터를 쌓을 '구글 시트'와, 알림을 받을 '구글 챗'을 Claude와 연결합니다.

3-1 · 작업 폴더 만들기

바탕화면에 crawling-practice 같은 폴더를 하나 만들고, Claude Code에서 그 폴더를 작업 폴더로 선택합니다. 앞으로 만들어지는 코드와 설정이 이 폴더에 모입니다.

3-2 · 데이터를 쌓을 구글 시트 만들기

구글 드라이브에서 새 스프레드시트를 만듭니다. 수집 결과가 여기에 날짜별로 쌓입니다. 주소창의 /d/ 와 /edit 사이 긴 문자열이 시트 ID입니다(나중에 Claude에게 알려줍니다).

3-3 · 서비스 계정 연결 (Claude가 시트에 쓰게 하기)

i서비스 계정이 왜 필요한가요?
사람이 아니라 프로그램이 쓰는 전용 구글 계정입니다. 이게 있어야 Claude가 만든 코드가 사람 로그인 없이도 시트에 자동으로 기록할 수 있습니다.
1
서비스 계정 JSON 키 발급Google Cloud 콘솔에서 서비스 계정을 만들고 JSON 키를 내려받아 작업 폴더에 넣습니다. (Claude에게 "서비스 계정 만드는 법 알려줘"라고 물어도 됩니다.)
2
시트에 편집 권한 공유 (중요)만든 시트의 [공유]에서 서비스 계정 이메일(예: ...@....iam.gserviceaccount.com)을 '편집자'로 추가합니다. 이걸 빠뜨리면 "권한 없음"으로 기록이 실패합니다.

3-4 · 알림 받을 구글 챗 웹훅 만들기

i웹훅(Webhook)이 뭔가요?
"여기로 메시지를 보내면 이 채팅방에 표시된다"는 전용 주소입니다. 구글 챗 스페이스 설정에서 만들 수 있고, 이 주소로 자동화가 알림을 보냅니다.
1
알림 받을 스페이스 열기 → 웹훅 추가구글 챗 스페이스 이름 클릭 → 앱 및 통합 → 웹훅 관리 → 이름 입력 후 저장.
2
URL 복사 → Claude에게 전달생성된 웹훅 URL을 복사해 .env 파일에 저장하거나 Claude에게 직접 알려줍니다.
!키·URL은 비밀번호처럼
서비스 계정 키와 웹훅 URL은 비밀번호와 같습니다. 코드나 문서에 직접 쓰지 말고 .env 파일에만 저장하세요. 외부(메신저·이메일)로 공유할 때는 특히 주의합니다.

i왜 세션을 저장하나요?
매번 로그인하면 자동화가 안 됩니다. 한 번 로그인한 브라우저 상태(쿠키·토큰)를 파일로 저장(storageState)해두면, 사람 없이도 매일 수집할 수 있습니다.

로그인 세션 저장 (최초 1회)

1
내 터미널에서 세션 저장 스크립트 실행브라우저 창이 열립니다. Claude Code 안이 아니라 진짜 터미널에서 실행해야 창이 뜹니다.
2
브라우저 창에서 본인 계정으로 로그인평소처럼 AirDNA에 로그인합니다.
3
대시보드가 뜨면 자동 저장로그인 완료를 감지해 세션을 .auth/airdna_state.json에 저장하고 창을 닫습니다.
4
이후엔 로그인 없이 수집저장된 세션을 재사용하므로 다음부터는 바로 수집됩니다(약 30일 유효).

!실제 사고 사례 — 과도한 호출 주의
한 자동화가 사내 방 검색 API를 짧은 주기로 대량 호출해, 일부 사용자의 검색·지도 화면이 일시적으로 느려진 일이 있었습니다. 예방하려면: 호출 주기·건수를 제한하고, 같은 요청을 무한 반복(루프)하지 않도록 종료 조건을 확인하며, 테스트는 소량으로 합니다.

꼭 지킬 안전 수칙

  • 공개 데이터만. 로그인 뒤 개인정보·유료 데이터를 무단 수집하지 않습니다.
  • 약관·robots 존중, 과도한 호출 금지. 주기는 넉넉히, 테스트는 소량으로.
  • 키·세션은 문서·메신저에 남기지 않기. .env·.auth/에만 두고 커밋·공유 금지.
  • 결과는 항상 눈으로 한 번 확인. 숫자가 0이거나 비면 페이지 로딩·셀렉터를 의심합니다.

9.자주 묻는 질문 · 용어집

막힐 때 빠르게 찾아보는 장입니다.

자주 묻는 질문(FAQ)

Q. 코딩을 전혀 몰라도 되나요?
네. 말(자연어)로 "어디를·무엇을·어디에"를 요청하면 Claude가 코드를 대신 만듭니다.
Q. 결과가 0이거나 비어 있어요.
페이지가 다 뜨기 전에 읽었을 가능성이 큽니다. "값이 화면에 나타날 때까지 기다렸다가 읽어줘"라고 덧붙이세요.
Q. 로그인이 필요한 사이트는 어떻게 하나요?
실습 ④처럼 한 번 로그인해 세션(storageState)을 저장하고 재사용합니다. 매번 로그인할 필요가 없습니다.
Q. '자격 증명 오류'·'권한 없음'이 나요.
시트를 서비스 계정 이메일에 '편집자'로 공유했는지 확인하세요. 세션 만료(로그인 사이트)라면 세션을 다시 저장합니다.
Q. 한글이 깨져요.
사이트 인코딩이 EUC-KR일 수 있습니다. Playwright(브라우저)는 자동 처리하지만, 직접 요청 방식이라면 "EUC-KR로 디코딩해줘"라고 요청하세요.
Q. 자꾸 차단당해요.
호출이 너무 잦을 수 있습니다. 주기를 넉넉히 잡고, 같은 요청을 반복하지 않도록 종료 조건을 확인하세요.
Q. 회사 서비스에 부담을 줄 수도 있나요?
네. 운영 중인 API/사이트를 짧은 주기로 대량 호출하면 장애를 일으킬 수 있습니다(8장 사고 사례 참고). 호출 주기·건수를 반드시 제한하세요.

한눈에 보는 용어집

크롤링(Crawling) — 웹페이지를 자동으로 열어 데이터를 긁어오는 것. 스크래핑과 같은 뜻으로 씀.
Playwright — 진짜 브라우저를 실행해 페이지를 열고 클릭·로그인·읽기를 대신하는 자동화 도구('손가락').
Claude Code — 자연어 요청을 이해해 코드를 설계·작성하는 AI 도구('두뇌').
API — 사이트가 데이터를 프로그램용으로 내려주는 공식 창구. 있으면 크롤링보다 안정적.
셀렉터(Selector) — 페이지 안의 특정 값을 콕 집어 가리키는 주소.
서비스 계정 — 사람이 아니라 프로그램이 쓰는 구글 계정. 시트 접근을 위해 '편집자'로 공유해야 함.
웹훅(Webhook) — "여기로 보내면 이 채팅방에 표시된다"는 전용 수신 주소.
세션·storageState — 로그인한 브라우저 상태(쿠키·토큰)를 저장해 재사용하는 것. 로그인 사이트 자동화의 핵심.
EUC-KR — 옛 한글 인코딩(UTF-8 아님). 안 맞으면 한글이 깨짐.
프레임셋 — 여러 페이지를 한 화면에 끼워 넣는 옛 구조. 진짜 데이터는 안쪽 다른 주소에 있을 수 있음.
